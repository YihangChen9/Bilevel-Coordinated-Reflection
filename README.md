# Bilevel Coordinated Reflection (SRMA)

Reference implementation for *Bilevel Coordinated Reflection: A Game-Theoretic Approach to
Multi-Agent LLM Systems*. It provides the bilevel orchestrator–worker framework and
**Stochastic Reflective Memory Ascent (SRMA)**, with two coordination testbeds:
**Resource Contest (RC)** and **Overcooked (OC)**.

> This release covers the RC and OC scenarios. The SWE-bench scenario will be open-sourced separately later.

All agents are **frozen LLMs** called through an OpenAI-compatible endpoint; the only
adaptation is textual memory editing (no weights are trained or shipped). Every reported
metric is computed from environment ground truth — never from an LLM judge.

---

## 1. What SRMA is

A candidate reflection is committed to shared memory **only when a deterministic, grounded
verifier risk `ρ` strictly decreases** (the gate). The verifier is scenario-specific:

| Scenario | Verifier risk `ρ` | Primary metric |
|---|---|---|
| Resource Contest | # workers with a concrete, environment-consistent cap claim | cumulative reward / regret |
| Overcooked | exact BFS value table `V(s)` = joint-action steps to next delivery | deliveries / score |

The upper level (orchestrator) decomposes the task and evolves a strategy memory across
episodes; the lower level (workers) read the full shared workboard, propose reflections,
and commit them only on `ρ`-descent.

## 2. Requirements

- Python **3.10–3.12**
- An OpenAI-compatible LLM endpoint (any provider; configured via `.env`, see §4)

---

## 3. Install

```bash
python -m venv .venv && source .venv/bin/activate

pip install -e .                    # core: Resource Contest + framework
pip install -e ".[overcooked]"      # Overcooked (uses overcooked_ai; pins numpy<2, scipy<1.13)
pip install -e ".[dev]"             # tests + plotting
```

> Overcooked pins `numpy<2` / `scipy<1.13` (required by `overcooked_ai`). If this clashes
> with other packages in your environment, use a dedicated virtualenv for `[overcooked]`.

---

## 4. Configure LLM access

Create a `.env` at the repo root (OpenAI-compatible endpoint):

```
LLM_API=openai
OPENAI_API_BASE=<your-endpoint>/v1
OPENAI_API_KEY=<your-key>
LLM_MODEL=<model-name>
LLM_MAX_TOKENS=2048
```

## 6. Running the experiments

### Resource Contest
```bash
python -m experiments.rc.run --config easy            # one config
python -m experiments.rc.run_ablation --models <M> --variants algorithm_complete
```
Configs (`experiments/rc/configs.py`): `easy` (N=3, caps (3,5,8), T=15), `hard` (N=3,
(6,7,8), T=20), `many` (N=6, (2,4,5,6,7,9), T=20), `drift` (N=3, (3,5,8)→(9,5,4) at t=10).
Metric: cumulative reward / regret against the oracle `G*_t = max_i M_i`
(oracle Σ-reward 120 / 160 / 180 on easy/hard/many). The variant that fully realises the
algorithm is `algorithm_complete` (gated workboard writes + strategy reads workboard).

### Overcooked
```bash
python -m experiments.oc.run --config cramped_room    # bilevel + oracle/random baselines
python -m experiments.oc.run_gate --seeds 0 1 2       # gate vs. no-gate ablation
python -m experiments.oc._calibrate                   # drift-law β from gate logs
```
Layouts: `cramped_room`, `asymmetric_advantages`, `centre_pots`, plus hard-coordination
`coordination_ring`, `forced_coordination`, `counter_circuit`. Metric: deliveries / score.

## 7. Repository layout

```
worker/            ReAct agent, roles, tools, pre/post-step memory hooks
env/               Environment protocol + local stub
memory/            Markdown-backed memory ports (orch_log / workboard / agent scratch)
orchestrator/      llm.py (LiteLLM wrapper) + orchestrator.py (bilevel dispatcher)

  resource_contest/  game, roles, strategy, gated-reflection tools, baselines

```
